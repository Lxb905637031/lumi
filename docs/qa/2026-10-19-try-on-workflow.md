# 显式试穿输入、额度展示与客户端恢复验证

## 实现范围

替换默认取第一条档案/衣物的行为；用户主动登录/加载，分页、显式选择带照片的最新人物版本及单件衣物，确认版本/单品/预留次数后提交。额度从服务端读取，不新增购买或客户端赠送入口。

按企业分层拆分为平台无关 `TryOnWorkflow`、Taro 生命周期 hook、原生输入选择组件、额度展示组件和 API adapter。沿用现有 Lumi 排版/组件/样式，不新建平行设计系统。设计 Brief/状态矩阵先于实现更新；ui-craft 不可用，故不开展视觉精修。

## 运行边界

- 生成仍是 local-svg，不是真实 AI；图片内容为隔离 fixture，不是效果验收。
- HTTP 联调用注入 adapter 运行同一工作流，**不是 Taro.request、Picker、showModal 或微信渲染验收**；页面构建也不是微信工具/真机验收。
- 输入/未知提交只在当前 app 内存会话中保留，不把照片/测量值/签名凭据写入磁盘；应用被系统杀掉后应从生成记录查询，不承诺跨冷启动自动续提。
- 当前列表仅提供档案最新版本，历史版本选择/参数冲突决策仍未完成；已有旧任务无快照时也不能伪称“原始快照”。
- 原生弹层/弱网、离开恢复、双端键盘安全区及视觉同视口对照仍待微信开发者工具和 iOS/Android。完整后台额度配置、真实模型和生产发布仍未完成。
- 测试只清理本轮用户及关联数据，私有对象先进入持久清理队列，不清空桶、不重置数据库。
