# 生成额度与中断恢复验证（本机）

## 范围与环境

PostgreSQL 16、Redis 7、真实 Nest/Fastify HTTP、私有 SeaweedFS；生成仍为 `FREE_MODE/local-svg`。免费次数是开发配置，不是已经验收的商业定价。没有调用付费服务，没有部署生产。

## 通过的验证

- `pnpm check`：格式、Lint、全 workspace 类型检查、17 项 API 单测、Nest/Vite/Taro weapp 构建。
- `DATABASE_URL=… pnpm --filter @lumi/api test:quota`：11 个 PostgreSQL 场景（测试框架另计外层容器），使用随机隔离 schema，结束后仅清理本次 schema。
- 单次赠送与数据库非负/守恒约束；并发同键只创建一次、不同输入冲突；人物/衣物输入快照不随原资料编辑而改变。
- 9 个不同请求竞争 5 次额度；成功/失败/取消/重试的账户余额均与账本聚合一致。自动重试沿用预留；并发人工重试只新增一个批次；旧批次消息不能执行新批次。
- 8 轮“9 个并发提交 + 同时执行 worker”验证，40 个成功任务各只结算/通知一次，不超额、不死锁。
- 模拟队列投递失败退款、数据库落库后补投、Redis 短暂失败保留任务、长时间未启动退款；两次并发恢复只退款/通知一次。
- 暂停 provider 后使租约过期，恢复/人工重试后旧 worker 返回不能写入输出/扣次；执行中取消同样阻止迟到输出。
- 旧任务 attempt=0 不追扣、不伪造输入快照；旧库升级回归加入旧生成任务，验证原数据/空快照/空额度表保留。
- 真实 HTTP 主链路：121 次带状态断言的 API 请求、另 2 次 CORS 校验。增加额度鉴权、本人数据、分页、禁客户端增额、同键冲突、成功结算、并发额度耗尽及不创建超额任务。
- 私有对象存储专项回归：34 次计数 API、3 次并发 complete、2 次 complete/delete 竞争，以及真实 S3 上传/读取/拒绝/清理。
- `pnpm test:migrations`：空库、重复 deploy、旧 db-push 库纳管升级、schema 精确匹配与远程保护。增量迁移已经应用到本机既有库，无重置或历史改写。

## 联调发现与修复

最初 HTTP 并发运行暴露 PostgreSQL 40P01：用户行 `FOR UPDATE` 与 worker 媒体/通知外键检查产生锁反转，接口返回 500。改为 `FOR NO KEY UPDATE`，保留用户内串行但允许外键 KEY SHARE；补上交叠提交/执行回归，修复后完整 HTTP 再跑通过。首次请求在 API 尚未就绪时连接失败，健康检查通过后重跑；此失败不计入通过请求数。
