# 免费试穿额度与任务一致性

依据 PRD 5.3/7：成功才实际消耗，失败返还，支付保持关闭。开发默认一次性体验 5 次，通过服务端 `FREE_TRIAL_CREDITS` 配置；这是开发策略，不代表生产定价/赠送活动已验收。

## 不变量

- 每用户一份账户，available + reserved + consumed = granted，三类余额不为负，数据库 CHECK 约束兜底。
- 创建任务与预留 1 次额度在同一 PostgreSQL 事务；相同用户/幂等键只产生同任务、同预留；同键不同输入返回冲突。
- 初始赠送、预留、结算和释放都有追加账本，事件键唯一。客户端不能提交或修改余额。
- 自动重试沿用同一次预留；成功与消费、输出、通知原子提交；最终失败/取消与释放原子提交。人工重试为新的 attempt，再次预留；余额不足不启动。
- 老任务 quotaAttempt=0，明确 grandfather，不伪造旧账本、不追扣历史试穿。新任务保存不可变人物版本/衣物元数据与素材摘要快照，旧任务快照为 null，不伪造。

## 中断恢复

任务先持久化再投递；定时扫描未投递 QUEUED 任务并幂等补投，避免进程在事务提交后、Redis 投递前崩溃而永久占用额度。新任务执行有令牌/租约；失联执行超过租约转死信并释放，旧 worker 无权覆盖新状态。队列故障条件更新失败状态并释放，不靠前端重复点击退款。

当前开发队列边界：投递/取消调用最多等待 5 秒（迟到的 Redis 操作仍受数据库状态隔离）；每 15 秒最多扫描 50 条，排队超过 5 分钟或超过尝试上限转死信退款；执行租约 120 秒，provider 超时 60 秒。人工重试使用独立 Redis jobId，老队列消息缺少 quotaAttempt 时只匹配 legacy attempt=0。所有外部调用在数据库事务之外。

账户初始化与创建/人工重试以用户行 `FOR NO KEY UPDATE` 串行，不能使用会阻塞 worker 外键 KEY SHARE 检查的 `FOR UPDATE`；真实 HTTP 曾暴露该锁反转，已修复并增加提交与执行交叠的 PostgreSQL 回归。

接口：`GET /api/v1/quota` 返回自己的可用/预留/已消费/初始赠送和单次消耗；`GET /api/v1/quota/ledger?limit=…&cursor=…` 只返回自己的账本，不能传入余额或申请加次数。账户按首次使用懒创建，后续配置变化不为已有账户重复赠送。余额不足返回 409 `FREE_QUOTA_EXHAUSTED`，任务与预留均不落库。

真实模型尚未配置；超时、可取消 provider、算力和生产大规模故障演练仍须单独验收。账本/API 验证不能替代小程序生成前额度展示、完整后台额度配置或真实模型验收。

## 验收

实际 PostgreSQL 验证一次性赠送、并发超额拒绝、幂等请求/账本、成功结算、失败和取消释放、人工重试、故障窗口补投、过期 worker 令牌保护、旧任务兼容；升级测试验证旧用户/任务不被修改。所有 fixture 隔离，不重置原数据。
