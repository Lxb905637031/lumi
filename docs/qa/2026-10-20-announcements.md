# 公告与批量通知联调记录

日期：2026-10-20

## 已验证

- 管理员权限：普通用户访问公告管理接口返回 403，后台管理员登录后可创建和编辑草稿。
- 草稿幂等：相同 `idempotencyKey` 重复创建返回同一公告；标题和正文受 DTO 长度约束。
- 版本保护：旧 `expectedVersion` 更新返回 409，避免后台并发覆盖。
- 发布闭环：发布时在事务内锁定公告，使用单条 `INSERT ... SELECT` 快照当前 ACTIVE 用户，避免将全量用户 ID 加载到 API 进程内存；之后将公告 ID 放入 BullMQ/Redis 队列并立即返回 `SENDING`。
- 异步投递：消费者每批处理 250 位收件人，通知写入和收件人 `deliveredAt` 在同一事务内提交；队列使用有限次指数退避。
- 重试幂等：收件人主键和通知 `eventKey` 去重；消费者崩溃后 BullMQ 可重试，进程重启后的恢复扫描会重新派发仍为 `SENDING` 的公告；重复发布不会增加通知。
- 后台状态：发布后轮询投递进度，显示已送达数；最终状态为 `SENT`。
- 客户端读取：消息中心通过目标接口读取公告标题和正文，单条已读后状态保持。
- 数据库：12 条迁移在本地 PostgreSQL 部署成功；空库重复部署、基线升级和 schema diff 检查通过。

## 证据

`LUMI_API_URL=http://127.0.0.1:4341/api/v1 pnpm --filter @lumi/api test:announcements`：21 次真实 loopback HTTP 请求通过，覆盖异步 `SENDING → SENT` 和重复发布。完整 `pnpm check` 另覆盖当前工作区格式、lint、类型检查、单测和三端构建。

测试使用唯一的本地 fixture 用户，结束时删除公告、通知和账号；未调用外部服务或真实微信接口。
