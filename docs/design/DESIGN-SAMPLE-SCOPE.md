# Lumi 全量视觉样稿范围（待审）

日期：2026-10-20。此次只交设计稿，不修改生产小程序或后台 UI，不声称完成接口、微信运行时或上线验收。

## Brief 与阶段门

面向希望复用已有衣物、减少搭配试错的成年用户。核心任务是：建立私有人物资料 → 选择一件自己的衣物 → 审阅输入与额度 → 发起任务 → 确认结果 → 云端保存或审核后公开。

设计成功标准：每屏只有一个主任务；照片/参数默认私有；中断、失败、授权拒绝不会丢失有效输入；未知提交结果先查询而不创建第二次任务。此标准待选稿后验证，不能用样稿截图证明已经实现。

沿用 Taro / React / TypeScript 与现有 feature 分层。当前不调用付费设计服务、不引入新的线上 UI 组件系统。`ui-craft`、Product Design 与内置 ImageGen 本次不可用，使用确定性的 HTML/CSS 设计板与浏览器截图替代；没有使用收费 API。

## 三套方向（同内容比较）

- A / 发现优先：轻导航、双列不等高媒体流，参考 Pinterest 的浏览/保存任务结构，不复制其红色品牌语言。
- B / 衣橱优先：主参考 Whering 的衣橱分类与选择任务；目录式单品、紧凑的资产摘要、带上下文的下一步。作为完整展开样稿的默认展示方向，并非已选定方向。
- C / 编辑优先：大幅照片、少量编辑标题、较低内容密度；参考 Indyx 的个人衣橱服务与编辑内容层级，不复制其摄影、品牌字标或页面组合。

## 用户流、入口和状态

入口：直接打开回到浏览态；分享直达帖子保留回首页出口；消息直达原任务/原帖，失效时展示原因和返回；扫码/搜索直达私有页先校验登录再恢复原目标。

正常：发现/衣橱 → 私有人物资料 → 单件衣物 → 审阅 → 任务查询 → 确认 → 保存/发布 → 审核结果。

异常：拒绝授权仍可浏览；上传失败保留有效表单与成功图片；提交未知保留原幂等键；生成失败返还预留并允许明确重试；409 保留当前编辑、显示版本对比；被删除目标不给空白页。

浏览态：稳定底部导航。专注态（编辑、上传、审阅、发布、注销）：隐藏全局导航，保留退出与底部安全区；返回恢复草稿/原任务，不持久化照片签名或敏感参数到样稿。

灰度优先级：对象/媒体 → 当前状态 → 唯一主动作 → 次级说明 → 恢复入口；不以大营销 Hero、装饰渐变、虚构仪表盘、任意图标宫格或卡片套卡片承载核心任务。

每页共用状态：首次/局部 loading、首次空/筛选空、失败/离线/超时、未授权/拒绝、提交防重、成功、过期响应丢弃、再次进入恢复。32 张图是关键状态样例，不是全部状态笛卡尔积；选稿后须扩展为可测组件状态。
