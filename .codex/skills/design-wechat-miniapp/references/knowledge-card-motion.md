# 微信小程序知识卡动画流程

把动画当作知识解释和状态反馈，不当作装饰。先保证静态卡可独立传达事实，再让运动解释顺序、因果、变化或空间关系。

## 先判断是否需要动画

动画必须至少完成一项：

- 解释先后顺序；
- 解释因果关系；
- 展示形态、数量或空间关系的变化；
- 保持两个状态之间的空间连续性；
- 给用户操作即时、可理解的反馈。

先写“没有动画时哪里难懂、动画具体解决什么”。若静态图加标注同样清楚，保留静态卡。纯氛围和品牌装饰只能是可移除增强，不能成为知识载体。

## 三种知识卡动画级别

| 级别 | 适用内容 | 交互外壳 | 默认策略 |
|---|---|---|---|
| 卡内微演示 | 单一局部变化或操作反馈 | 卡片原位，预留高度 | 用户触发、短时、播一次、停终帧 |
| 短图解 | 一个顺序、因果或空间关系 | 卡内展开或轻量专注态 | 可暂停/重播，有海报和静态替代 |
| 分幕专注课程 | 多步骤、需解释或持续注意 | 独立非 TabBar 页面 | 分幕、可跳转、可退出、保存进度 |

不要把所有知识都做成视频。需要用户选择、拖动、比较或试错时，优先用真实组件或 Canvas 交互；视频只负责不可交互的线性讲解。

## 八道制作阶段门

### M0. 知识事实

定义事实来源、学习目标、常见误解、一句话静态结论、前置知识和术语。领域负责人先确认内容正确；动画不能修补错误或含糊的知识。

### M1. 动画价值

为一段动画只指定一个主要教学任务。区分反馈、转场、知识解释和品牌庆祝；后两者不能与操作反馈争抢注意。

### M2. 无声分幕

默认先做无声图解，再决定是否增加声音。一个知识点通常拆成少量明确的语义幕；每幕只解释一个变化。

| 字段 | 说明 |
|---|---|
| `beat_id` | 稳定且可恢复、可测试的幕编号 |
| 教学问题 | 本幕回答什么 |
| 起始/完成状态 | 变化前后各看到什么 |
| 变化对象 | 哪个对象发生变化 |
| 稳定锚点 | 哪些位置保持不动以帮助理解 |
| 轨迹 | 出现、移动、连接、替换或强调 |
| 字幕/标注 | 静音时仍能理解的说明 |
| 用户动作 | 自动推进、点击下一步或直接操纵 |
| 静态替代帧 | 精简、关闭和失败时显示什么 |

信息不得只存在于旁白、音效、颜色或瞬时运动中。文字仍在阅读时，不让多个对象同时运动；标签、箭头、编号和结果落在稳定终态。

### M3. 状态板

分别画知识语义、播放器和资源状态，不把三者混成一个布尔值：

```text
知识：intro → cause → change → result → recap
播放：poster → loading → ready → playing.beat-n ↔ paused → ended
异常：loading/playing → error
适配：任意状态 → reduced/static
资源：unloaded → fetching → ready/cached | failed
生命周期：playing → onHide/offscreen → paused → 等待用户继续
```

每个状态记录可见内容、控制、进入/退出条件、保存内容和测试 ID。状态板至少包括海报、加载、每一幕、暂停、结束、错误、精简/关闭、静音、切后台、弱网和再次进入。

### M4. 静态卡到播放

静态卡至少包含标题、一句话结论、有意义的首帧/示意图、播放按钮、时长/幕数和静态阅读入口。语义动画默认由用户触发，不在列表进入视口后自动播放。

短动画可在卡内展开；多幕或需要持续注意时进入专注态。保持标题、对象和空间关系连续，预留播放区高度。从专注态返回时恢复列表滚动位置和当前幕。同一视口只允许一个知识动画活动，离屏即暂停。

### M5. 关键帧与 Animatic

先排关键帧，再给时间：首帧、每幕结束帧、暂停帧、最终帧、错误帧和静态替代帧。用低成本 animatic 验证阅读时间、变化顺序和控制位置；未经确认不要直接制作复杂资产。

暂停必须停在清晰稳定的语义帧，不能停在模糊、遮挡或无意义的过渡中间态。结束后保留总结、“再看一遍”和自然下一步，不自动复位或强制跳转。

### M6. 资源与运行时

按本页技术选择表做最小 PoC，实测目标项目的基础库、渲染器、组件层级、内存和真机表现。输出海报、关键帧、字幕/标注、动画资源、静态替代、资源清单与 `beat_id` 时间线。

使用语义状态驱动动画；不要用多个定时器拼接。页面隐藏、离屏或卸载时暂停并释放非必要资源，返回后等待用户继续。

### M7. 失败、降级与验收

加载失败时保留静态卡和最后完成关键帧，说明“动画未加载，可查看图解”，提供静态图解和手动重试。不中断学习进度，不无限显示 Spinner。

完整、精简、关闭、静音、弱网和离线都必须完成相同学习目标。最后在微信开发者工具、iOS 与 Android 真机检查首次播放、暂停、重播、多次点击、切后台、离屏、再次进入、一屏多卡和资源失败。

## 播放器与资源状态

知识卡播放器至少提供：播放/暂停、重播、多幕的上一步/下一步、当前幕/进度、明确退出；有声音时提供静音和字幕。不要把点击画面同时定义成暂停、打开详情等多个动作。

结束时停在可读终态；失败时保留事实和恢复动作。答错反馈放在相关对象附近，用文字解释并保留原选择；不能只摇晃、变红或震动。

长线性内容不要 `autoplay` 或 `loop`。无音轨内容明确标注“无声图解”，不要保留一个看似故障的音量控制。

## 渲染方式选择

优先选择能用最小运行时成本完成教学任务的方式：

| 需求 | 优先方式 | 适用边界与注意 |
|---|---|---|
| 按下、选中、显隐、轻位移 | WXSS transition/keyframes | 优先 `transform` 与 `opacity`，避免通过布局属性持续重排 |
| 多步组件状态动画 | `this.animate` + `clearAnimation` | 用语义状态导出；已有旧代码才沿用 `wx.createAnimation`，先核对当前渲染器 |
| 路线、连线、坐标、战术或数据变化 | Canvas 2D + rAF | 按 DPR 设置明确尺寸；画完即停并 cancel；错误时落静态替代 |
| 矢量角色或复杂形变 | `lottie-miniprogram`，仅在 PoC 通过后 | 基于 Canvas；确认项目基础库；表达式不受支持；卸载时销毁实例 |
| 小型逐帧角色动作 | 序列帧/雪碧图 | 控制帧数、解码内存与循环；页面隐藏即停 |
| 长、复杂、非交互线性讲解 | Video + poster + chapter manifest | 用户触发、播一次、可暂停；弱网回退分步图，关键文字不要烧进视频 |
| 需要选择、拖动、试错 | 真实组件或 Canvas 互动 | 不要压平为不可操作视频，提供点击替代与 Undo |

Skyline worklet、共享元素或特定渲染器能力只在项目已经采用并完成兼容性验证时使用，不能为了一个转场迁移整个项目。不要逐帧 `setData`；它只负责开始、结束、选中等离散状态。Canvas、Video 等原生/同层组件与遮罩、弹层、滚动、裁剪的组合必须在 iOS/Android 真机验证，开发者工具不能单独背书。

微信官方 demo、API typings 和 `lottie-miniprogram` 仓库可作为能力核对入口；具体支持仍以当前项目基础库、渲染器与双端真机为准。包体、首播等待、帧率和内存没有跨项目通用预算；引用用户/仓库既有门槛或建立可复现实测基线。缺少证据时写 `TBD` 和测量计划，不自行填写确定数字。

## Motion Tokens

以下是起始范围，不是教学内容的固定总时长：

| 事件 | 建议范围 |
|---|---|
| 按下反馈 | 100–150ms |
| 选择或小状态变化 | 150–220ms |
| 展开、揭示、面板 | 200–320ms |
| 卡片到专注态 | 250–420ms |
| 正误反馈 | 350–550ms，播一次 |
| 路线/关系描线 | 1.2–1.8s，用户触发后停终帧 |

进入使用 ease-out，退出使用 ease-in，双向状态变化使用 ease-in-out。线性只用于确实表达匀速的进度或运动。一个视口最多一个常驻装饰动画；常驻动画必须能关闭并在页面隐藏时停止。

## 精简关闭与弱网

精简动画不是把原动画加速：改用带标注静态图或用户点击推进的离散关键帧，移除视差、弹跳、旋转、大幅缩放和长距离位移，必要反馈只保留短透明度变化。

不要假设微信提供与 Web `prefers-reduced-motion` 等价且可靠的公开信号。提供产品内“完整/精简/关闭”设置并持久化。关闭模式直接提交最终静态状态，不能把时长设为零后仍等待计时器；知识、控制和最终结果必须等价。

海报、首帧和静态替代优先随包或可靠缓存；复杂资源按需加载。短等待不要闪 Loading，较长等待显示局部加载。失败或超时立即退回静态图解。恢复按最后完成 `beat_id`，不按任意毫秒；切后台立即暂停，回来后不静默续播。

## 可测试交付

为测试提供固定 `beat_id`、`motion_state` 和可直接进入 poster/loading/playing/paused/ended/error/reduced 的调试入口。允许冻结或跳到语义关键帧；固定数据、时钟和随机值。

截图回归只比较关键帧，过渡中间帧单独排除。交付正常、精简/关闭、弱网/失败三类录屏，至少检查：

- 首次播放、暂停、继续、重播与退出；
- 多次快速点击和防重复启动；
- 切后台、回前台、离屏和再次进入；
- 静音、精简、关闭；
- 弱网、离线、超时和播放中断；
- 一屏多张知识卡；
- 超长标题、字幕、动态字号和不同屏宽；
- 微信开发者工具、iOS 与 Android 真机；
- 项目定义的资源体积、首播等待、内存和流畅度预算。

## 反模式

- 为高级感添加与知识理解无关的循环动画；
- 所有卡片进入视口后同时自动播放；
- 把语义藏在声音、颜色、震动、纸屑或 Toast 中；
- 用不可暂停长视频替代分幕结构；
- 结束后立即复位，暂停停在无意义中间帧；
- 失败时空白或无限 Spinner；
- 精简模式删除知识，或只是把原动画加速；
- 用多个 `setTimeout` 拼接流程；
- 简单状态变化引入大型 Video/Lottie；
- 在资源中烧录所有文字，导致无法动态字号、翻译或修正；
- 只测浏览器，没有测试微信生命周期和双端真机；
- 从静态竞品截图臆测并复制其动效。
