# App UI/UX 参考到微信小程序的模式迁移

本文件把真实 App 截图转成可复用的产品结构和微信小程序规则。它不提供“仿某 App”的捷径，也不替代 `ui-craft` 的间距、排版、层级、状态与可访问性规范。

本模式库来自一次离线研究样本：35 个 App 目录、7,534 张 PNG 截图，约 5.7 GB；原始截图不随 Skill 分发。用户另行提供参考目录时，先按任务抽样再迁移。截图是带日期的历史 iOS 快照，不代表当前版本，也不能证明真实动效、触感、VoiceOver、键盘焦点、动态字号或微信运行时表现。

## 迁移流程

### 1. 先定义任务，不先选风格

写清当前唯一任务、用户场景、风险等级、内容密度和成功结果。参考应回答一个任务问题，例如“第一次学习如何继续”“选完规格怎样确认总价”“中断后从哪里恢复”，而不是“怎样做得像 Duolingo”。

### 2. 选择参考组合

从同任务产品中选择 2–3 个参考，再选 1 个相反气质的参考用于检验取舍。不要一次扫描整个图库；先均匀抽看入口、中段和终点，再围绕目标任务连续看 5–9 张相邻截图。

### 3. 记录结构事实

每段截图必须记录：

| 项目 | 判断问题 |
|---|---|
| 任务时刻 | 用户此刻是在浏览、比较、学习、编辑、跟踪还是确认？ |
| 信息拓扑 | 连续画布、同质列表、媒体货架、自包含卡片还是上下文面板？ |
| 唯一主动作 | 当前最重要的动作是什么，位置是否在流程中稳定？ |
| 状态闭环 | 操作前、处理中、成功、失败和再次进入分别看到什么？ |
| 中断恢复 | 返回、切后台、弱网或拒绝权限后保留什么？ |
| 品牌边界 | 哪些是通用结构，哪些是来源 App 的识别资产？ |

### 4. 写迁移卡

使用以下格式，不能省略最后两列：

| 来源 App/连续片段 | 任务时刻 | 可迁移原则 | 微信小程序改写 | 明确不复制 |
|---|---|---|---|---|
| 例：学习产品的一题反馈段 | 回答后理解结果并继续 | 反馈贴近操作，选择与解释保留到下一步 | 专注页隐藏 TabBar；反馈面板避开胶囊和底部安全区；退出时保存题目进度 | 吉祥物、品牌色、连胜、虚拟货币、原文文案 |

### 5. 先做去品牌灰度骨架

先验证内容顺序、主动作、返回与状态，再使用当前产品的品牌载体。一个界面只选摄影、插画/IP、排版、数据可视化、材质或动效中的一个主要品牌载体，其余保持克制。

### 6. 用目标平台验证推断

截图只能作为设计假设。底部面板、地图、视频、键盘、权限、分享、支付和页面栈必须在微信开发者工具与 iOS/Android 真机验证。

## 页面拓扑与高频骨架

### 先选拓扑，再选容器

- **连续画布**：地图、学习路径、时间线、编辑器、实时数据。保持空间连续，工具放在边缘或上下文面板。
- **同质列表**：联系人、交易、设备、设置。依靠行、列线、分组和轻分隔，不给每行套卡片。
- **媒体货架/网格**：依靠图片快速浏览。只有素材质量、比例和裁切规则稳定时使用。
- **自包含卡片**：对象异质且各自有独立状态、元数据或操作。卡片不是默认容器。
- **上下文面板**：保留地图、内容或编辑对象时完成临时选择。复杂解释或深分支进入新页面；不要嵌套面板。

### 下一最佳动作首页

`当前上下文 → 当前成果/状态 → 唯一下一步 → 继续上次任务 → 少量次级发现 → 稳定导航`

首页先回答“现在该做什么”，再回答“还有什么”。促销、运营内容和低频能力不能与主任务同权。

### 引导式单步任务

`退出/返回 → 简洁进度 → 当前问题 → 必要说明 → 选择/输入 → 固定主 CTA → 持久反馈`

反馈必须保留用户选择、结果解释和继续动作。浏览页可保留 TabBar；答题、记录、播放、编辑等专注任务隐藏 TabBar，只保留退出、必要进度和主操作。

### 数据或地图主画布

`全屏数据/地图 → 边缘工具 → 当前对象高亮 → 可拉起摘要 → 主动作`

避免大卡片遮住画布。拖拽或路径操作必须同时提供点击/选择替代、Undo、大命中区和误触容错。

原始数据先改写成“行动窗口”：优先回答现在适合做什么、为什么、下一步是什么，再把完整指标放进二级详情。同一对象同时保留两个时间尺度，例如本次训练与周趋势、今日记录与年度轨迹；短期反馈推动行动，长期视图解释积累。

### 交易、配置与履约

`对象 → 选择/配置 → 价格和约束即时更新 → 审阅 → 支付/提交 → 状态轨道 → 下一事件/求助`

规格选择、备注和数量变化后，固定 CTA 同步显示结果或总价。提交后显示状态、预计下一步和可用行动，不只显示庆祝页。

### 高信任表单与确认

`目的与收益 → 一屏一决定 → 就地解释 → 输入/选择 → 审阅摘要 → 明确后果 → 提交处理中 → 可查询结果`

错误靠近字段并保留有效输入。高风险操作不能乐观更新，也不能靠动画或 Toast 作为唯一结果。

### 媒体发现与继续消费

`继续入口 → 主内容 → 少量问题导向分组 → 货架/网格 → 搜索/收藏 → 消费后下一步`

每个货架回答不同用户问题；若只是换标题展示同类内容，合并并使用筛选。

详情页使用“证据阶梯”：`对象/媒体 → 可用性或关键动作 → 摘要 → 背景/材料/章节 → 相关内容`。先让用户判断是否继续，再渐进展开证明与深层信息。

## 微信小程序改写表

| iOS/App 常见模式 | 微信小程序改写 |
|---|---|
| iOS 大标题导航和系统返回 | 先决定原生或自定义导航；避开状态栏与右上角胶囊；扫码/分享直达次级页时提供回首页路径 |
| 固定底部 TabBar | 只放 3–5 个跨会话稳定目的地；专注任务进入非 TabBar 页，退出后恢复原浏览上下文 |
| 半屏/底部 Sheet | 检查层级、遮罩、滚动穿透、键盘顶起、底部安全区及原生组件覆盖关系；不嵌套 Sheet |
| Deep Link | 分别设计微信搜索、小程序码、扫码、分享卡片、订阅消息和最近使用入口的初始上下文与返回 |
| 系统权限弹窗 | 先解释价值，临用才申请；拒绝后提供手输、稍后或受限模式，不把用户留在死路 |
| 长时间 App 会话 | 拆成短任务；保存草稿、筛选、滚动与进度；首页提供继续入口并说明上次状态 |
| 推送通知 | 只在用户动作后请求订阅消息；说明触发场景，拒绝后核心流程仍可完成 |
| 原生分享 | 设计分享标题、图片、落地页上下文、权限和失效状态；返回时恢复原任务 |
| App 内支付 | 使用 `wx.requestPayment` 时防重复提交；处理中不可离开关键状态；未知结果可查询、重试或安全退出 |
| 大体积视频/媒体 | 播放前公开时长、声音、流量或缓存状态；弱网有海报、文字摘要和重试；页面隐藏即停止非必要播放 |
| 地图与长时间运动记录 | 验证 `<map>` 原生层级与 `cover-view`；定位拒绝后允许手选城市；后台 GPS 受平台能力与审核限制，不能承诺与原生 App 等价 |
| 计时器与长任务 | 保存目标时间戳并在恢复时重算，不能依赖前台 `setInterval`；切后台、锁屏、来电和系统回收后都要有可读状态 |
| 相机、蓝牙与输入键盘 | 在真实微信运行时测试权限、原生层级、后台恢复、焦点、键盘顶起和 iOS/Android 差异 |

## 状态、动效与再次进入

- 按下反馈先出现，再让对象完成过渡，最后停在可读终态；错误或成功不能只存在于 shake、纸屑或 Toast。
- 正误、完成或选择反馈优先出现在操作位置，详细解释按需展开；庆祝不能遮挡结果或阻断下一步。
- 乐观更新只用于低风险、易回滚操作。支付、删除、报名和正式提交必须显示处理中并防重复触发。
- 同一视口最多一个常驻动效；提供完整、精简、关闭三档时，关闭后状态与信息仍完整。
- 返回后恢复滚动位置、筛选、输入和任务进度。错误时保住用户数据并提供就地重试。
- 沉浸内容开始前公开时长、段数和模式；进行中可暂停或退出；结束时给摘要和一个自然的下一步。
- 浏览态与专注态必须成对设计：专注态退出时保存进度，浏览态提供明显的继续入口。

## 迁移边界与反模式

### 可以迁移

- 内容顺序、操作优先级和信息密度；
- 页面拓扑、导航层级和上下文保留方式；
- 状态闭环、错误恢复和再次进入；
- 动效意图与反馈节奏，不是动效造型本身。

### 不得直接迁移

- Logo、角色、插画、摄影、商品图和品牌文案；
- 标志性配色、独有图标、声音、动效造型和奖励系统；
- 具有明显来源识别度的整屏组合；
- iOS 状态栏、系统控件或只在来源平台成立的交互；
- 促销轰炸、惩罚性连胜、公开排行和其他暗黑模式。

输出前做“去品牌测试”：移除来源 App 名、Logo 和主色后，方案是否仍能更好地完成当前产品任务？如果不能，说明只复制了表面。

| 反模式 | 风险 | 修正 |
|---|---|---|
| 只看首页或一张截图 | 漏掉错误、恢复、确认和再次进入 | 连续查看完整任务片段 |
| 把 App 名当风格提示词 | 只换颜色、圆角与插画，任务结构仍错 | 指明具体任务时刻和结构决策 |
| 每区都做卡片 | 关系被切碎，形成卡片汤 | 重新选择画布、列表、货架、卡片或面板 |
| 同时借多个品牌招牌手法 | 页面失去单一视觉语法 | 只选一个当前产品的品牌载体，其余借结构 |
| 用动效替代状态 | 动效结束后结果不可读 | 让终态文字、形状和数据独立可懂 |
| 没有正式素材却套媒体首页 | 大片占位，内容可信度低 | 改用排版/数据骨架或先准备资产 |
