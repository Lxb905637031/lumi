# Lumi Definition of Done

## 每个 Pull Request

- 业务代码归属到 feature；页面只组合 feature 和跨 feature UI，不把 API 调用或业务编排塞进页面。
- 每个外部输入有运行时 DTO/验证；API 响应不直接暴露 Prisma model。
- 加载、空、成功、失败、重试和重复提交状态有明确定义；异步写操作具备幂等策略。
- 新增/修改行为有自动化测试；契约变化同时验证 API 与依赖它的客户端。
- 执行 `pnpm check`，并在 PR 中说明未覆盖的手工验收项。
- 涉及设计的变更附同一视口/状态的截图证据，引用竞品时提交原则迁移记录，不复制品牌资产。

## 发布候选版本

- API：迁移脚本在干净数据库和上一版数据上验证；鉴权、越权、校验、限流、超时和错误响应通过测试。
- 小程序：微信开发者工具构建通过；授权拒绝、弱网、图片权限、键盘/安全区和核心闭环在 iOS/Android 真机验收。
- 后台：只展示服务端真实数据；具备登录、RBAC、写操作审计、分页、错误恢复与敏感操作确认。当前 token 注入和本地 admin 映射仅用于开发验收，不能替代正式后台登录。
- 媒体与生成：配置私有对象存储、签名上传/下载、内容审核、真实 provider、持久化任务队列、重试和人工恢复。
- 运行保障：生产密钥来自部署环境；启用 HTTPS、备份恢复演练、结构化日志、指标/告警、健康检查和回滚方案。
- 安全与合规：个人照片有明确授权、保存期限、删除流程、访问审计和隐私政策；第三方模型的数据处理约束完成评估。
- 交付：版本号、变更记录、部署步骤、数据库变更、回滚步骤、已知风险和负责人齐全。

## 当前 Lumi 状态

当前仓库只满足开发阶段基础：monorepo、严格 TypeScript、共享 API 类型、feature 拆分、Taro 与后台组件基础、API smoke test、静态构建、本地 FREE_MODE 联调，以及审核 API/RBAC/审计的开发垂直切片。后台正式登录、mock 生成队列、缺失的真实媒体上传/AI provider、持久化队列、真机验收仍是发布阻塞项；不能将当前状态标记为生产就绪。
