# 管理端权限矩阵

当前后端使用静态、版本控制的权限映射；用户表角色为 `USER`、`MODERATOR`、`ADMIN`。路由声明所需权限，认证守卫从有效会话读取数据库中的当前角色，再由授权守卫校验角色和权限。变更角色会立即影响后续请求，不依赖旧 access token 中的角色快照。

| 权限                       | USER | MODERATOR | ADMIN | 作用域                                     |
| -------------------------- | ---- | --------- | ----- | ------------------------------------------ |
| `MODERATION_READ`          | 否   | 是        | 是    | 帖子、评论审核队列及评论审核历史           |
| `MODERATION_WRITE`         | 否   | 是        | 是    | 帖子、评论单条及批量状态裁决               |
| `MEDIA_REVIEW_READ`        | 否   | 是        | 是    | 人物、衣物、生成结果与上传图片队列及历史   |
| `MEDIA_REVIEW_WRITE`       | 否   | 是        | 是    | 图片单条及批量审核                         |
| `REPORT_READ`              | 否   | 是        | 是    | 举报队列                                   |
| `REPORT_RESOLVE`           | 否   | 是        | 是    | 举报裁决                                   |
| `OPERATIONS_OVERVIEW_READ` | 否   | 是        | 是    | 运营总览                                   |
| `AUDIT_READ`               | 否   | 否        | 是    | 跨内容类型的全局审计检索，包含用户处罚变更 |

用户处罚、角色管理、账号隐私处理、运行配置、公告和挑战运营目前仍由 `ADMIN` 角色限定。普通用户即使持有有效会话也不能访问后台工作台；无效会话返回 401，角色或权限不足返回 403。

该矩阵是服务端静态策略，不代表后台已提供逐人授权界面，也不支持组织/租户级角色、自定义权限包或审批流。当前只覆盖代码中明确声明权限的审核、举报、总览和全局审计路由；未声明细粒度权限但带 `@Roles` 的管理路由继续由角色限制。生产部署、人员操作审计和值守仍需单独验收。

本机验证范围和命令见 [权限矩阵验证](../qa/2026-10-23-admin-permissions.md)。
