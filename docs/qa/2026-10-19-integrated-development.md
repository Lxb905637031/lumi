执行 HTTP 回归前需启动本地 Postgres、Redis 和 API，并用 workspace-root .env 配置 DATABASE_URL、REDIS_URL、JWT_ACCESS_SECRET、FREE_MODE=true 和允许的本地 CORS 来源。

```sh
pnpm infra:up
pnpm db:generate
pnpm db:push
pnpm dev:api
# 在另一个终端执行
pnpm check
pnpm --filter @lumi/api test:integration
```

db:push 仅用于本地，不能照此部署生产。脚本拒绝非回环 API 地址和非免费开发模式；每次生成唯一 fixture，只清理本轮用户/关联数据，不清空已有数据库。

HTTP 覆盖：

1. 健康检查、FREE_MODE 与 CORS 允许/拒绝来源。
2. 后台盐化密码登录、错误密码、普通用户 RBAC 拒绝和真实指标。
3. 图片拥有权、伪造格式拒绝、外人不可引用图片建档或建立衣物资料。
4. 六参数、档案版本冲突 409、资料拥有权、衣物修改及游标跨页不重复。
5. 异步生成、同键同任务、私有输出、死信任务人工恢复、取消和重复取消。
6. 图文必选图片、待审不可见、审核事务/审计去重、公开 Feed/详情、并发点赞和收藏。
7. 待审评论不可见且不计数、评论审核/审计、本人删除和举报提交。
8. 审核/生成通知、目标 ID、未读数、单条和全部已读、跨用户拒绝。
9. 本人删除、档案停用后禁止创建新任务。
10. refresh 轮换后可访问、重放撤销新会话、退出即失效和封禁账号不能重新登录。

## 后台真实浏览器

按仓库 Playwright skill 操作真实 Chromium，访问本地 Vite 与真实 API，未用 fixture 替代接口响应：

- 通过表单使用本轮专用管理员账号登录，工作台读取真实指标和审核列表。
- 仅对本轮新建的 browser-post 测试帖点击“通过”，页面由待审更新为已通过；不操作原有内容。
- 将本轮浏览器 access token 改为无效值后刷新：开发 StrictMode 的 4 个并行 401 只触发 1 次 refresh（201），随后 4 个请求恢复为 200。
- 同时令 access/refresh token 无效后，refresh 返回 401，自动返回登录表单。
- 再次正常登录并点击退出，返回登录页。
- 控制台出现的 401 均来自主动失效测试，没有据此宣称“零错误”；这不是生产安全审计。
