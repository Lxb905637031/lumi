# 私有图片链路设计与验收边界

## 信任与模块边界

MediaModule 管理拥有权、上传租约、图片处理和清理；对象存储通过端口注入。客户端不能提供 objectKey、桶名、最终 MIME 或摘要。S3 桶始终私有；公开帖子也只从审核通过且未删除的帖子签发短时 URL，不修改桶为公开。

本地基础设施采用 Apache-2.0 的 SeaweedFS 4.48 提供 S3 协议。原 MinIO latest/固定旧 tag 在本环境拉取被拒绝且官方旧二进制返回 410，因此替换开发运行组件；业务不绑定具体 S3 品牌。旧 MinIO 卷保留、不删除。单节点 compose 仅用于开发，不等于生产高可用。

## 状态与协议

1. 登录用户预留上传：校验 1B—5MiB、JPEG/PNG/WebP，建立 PENDING 资产和 5 分钟 staging 租约；签名 POST 只允许固定 key、声明类型和字节大小。
2. 客户端直传对象存储，再调用 complete。服务端以 CAS/带令牌租约转 PROCESSING，读取真实对象并限制字节数；完整解码、限制 1600 万输入像素、纠正方向、缩到最长 2048、剥离元数据并重新编码 WebP。
3. 写入仅服务端可写的独立最终 key，CAS 提交 READY 与尺寸/摘要；并发 complete 不重复创建资产。重复 READY complete 返回同资产；过期、伪造文件或越权不会产生可用资产。
4. 读取先校验拥有权或帖子审核上下文，再签发 60 秒 URL；旧开发 base64/SVG 仍单独标识 local，不自动升级为生产资产。
5. 删除先在数据库撤销可访问性并持久化对象清理任务，再异步幂等删除对象。签名租约到期后清理 staging，避免旧签名重传产生孤儿。临时 final key 在写入前登记延迟清理任务，成功提交后取消；中断/崩溃可以自动回收。

数据库与 S3 没有分布式事务，不宣称物理删除瞬时完成；已签发 URL 在 TTL 内可能继续有效。清理失败有退避与可查询记录，不能吞掉错误或把数据库软删除当成物理清理证据。

## 验收

- 单测：伪造/截断图片、MIME 不符、像素限制、元数据清除、缩放、配置失败关闭。
- 实际本机 S3+PostgreSQL+Nest HTTP：匿名读取/列桶拒绝，签名直传、完成、短时读取，固定 key/大小 policy，越权、重复、并发、过期、删除及清理恢复。
- 旧库迁移测试验证 legacy 默认 READY/local，既有记录不删除。
- Taro 上传服务接签名 POST；微信 uploadFile 进度/断网恢复仍需开发者工具和真机，未验收不能勾选 W08。

## 未关闭的发布门槛

生产 HTTPS/微信上传和下载合法域名、独立最小权限 S3 账户、容量/备份/审计、内容安全审核、照片姿态质量检查及生产故障演练仍须独立验收。完整解码/转码不是违法内容审核，也不代表试穿输入质量合格。
