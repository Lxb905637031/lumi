# 社区发布幂等与客户端恢复

对应 C08。本阶段延续结果发布与审核链路，不涉及微信好友分享/真实 AI。

- 新发布请求必须包含 8—128 字符 `idempotencyKey`；同拥有者同键、相同规范化内容返回同帖子，不同内容返回 409。事务锁用户行并以 `(authorId,idempotencyKey)` 唯一约束兜底。已有帖子保留 null，不伪造历史请求。
- 指纹包含去首尾空格的标题/正文/话题、按显示顺序的图片 ID 和用户声明的 AI 标记；服务端另行强制生成结果 AI 标记。重复请求先查已持久化帖子，故审核状态变化/原图片后来不可用不造成重复创建。已删除的同键请求返回冲突，不复活帖子。
- 图片权限/可用性、生成确认与图片行锁仍在同一事务中。为 JSON 图片引用加 GIN 索引，为结果图片引用加组合索引。
- 小程序业务流程抽成无 Taro/React 依赖的工作流，UI 仅渲染和适配平台。未知网络/5xx 结果保留不可变内容与原键，禁用编辑，仅可继续原发布或查询我的帖子；不得自动生成新键。确定的 4xx 错误允许修改后重新提交。
- 草稿仅在当前 app 会话内存保留，按认证会话隔离；不持久化私有 URL、图片路径或身体数据。旧版无账号绑定的磁盘草稿不自动读取，不擅自删除；新草稿不复用该存储键。
- 结果模式从已授权任务重新加载确认结果与媒体；发出发布请求前再次检查。离开停止渲染更新，已发出的未知请求仍保留原意图用于再次进入恢复；账号切换清除草稿/结果/意图并屏蔽旧异步响应。

验收：实际 HTTP 并发同键一次创建、异输入冲突、账号隔离、删除不复活、DTO 缺键/纯空白拒绝、结果发布/审核兼容；客户端单测涵盖双击、响应丢失、输入锁、离开恢复、会话切换、选图上传失败与草稿保留。另以相同客户端工作流连接实际 API 模拟服务端提交后丢失响应。
